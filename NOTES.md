# Maintenance notes

Decisions in this site that aren't obvious from the markup, and the reasons they're hard to reverse.
Kept here rather than in HTML comments — the site is served as plain files, so anything in
`index.html` is public.

## Hard rules

- **The cookieless analytics beacon is the only external request any page may make on load.** No
  third-party fonts, no CDN scripts, no embeds, no advertising or conversion pixels. `privacy.html`
  describes the current setup accurately; adding anything else makes it false.
- **The Cloudflare beacon token is a public site identifier**, not a secret. It's meant to sit in the
  markup.
- **Vocal Slice is free and open source (GPL-3.0) since 2.x.** The pricing section became the
  `#open-source` section, the Polar checkout and its attribution plumbing are gone, and
  `store-copy.md` was deleted. Don't reintroduce a price, a buy button or a trial anywhere — the app
  has no licence gate to back them up. Source and releases are both at
  `github.com/terranivium/vocal-slice`.

## Head

- **Platform detection runs inline in `<head>`, before `<body>`.** Both OS download buttons are in the
  markup so the page works with JS off; CSS hides the non-matching one via `[data-os]` on `<html>`.
  Setting that attribute after the hero had painted caused a visible reflow — "See how it works"
  jumped sideways as a button vanished. If neither signal resolves we set nothing and both buttons
  stay, which fails to a working state rather than guessing wrong.
- iPhone/iPad UA strings contain "Mac", hence the explicit iOS exclusion. An iPad visitor offered a
  `.dmg` is worse than one offered nothing.
- **Open Graph needs absolute URLs.** Relative ones are ignored and the link renders as bare text.
- **JSON-LD omits `softwareVersion` and `aggregateRating` deliberately.** The version is
  `{major}.{commit count}.0` and would be stale within days. There are no ratings, and inventing them is
  review fraud that Google acts on. Add ratings only when real and attributable.
- **The `Offer` is price 0**, with `isAccessibleForFree`, `license` and `codeRepository` beside it.
  It was a bare 29 USD `Offer` while the app was sold (one-time from Aug 2026, yearly before that).

## Body

- **Download is primary everywhere**, including the open-source card, whose secondary action is the
  source on GitHub.
- **On phones (≤700px) the download buttons swap to "Get notified".** You can't install a desktop app
  there, so the signup captures the visitor instead.
- **`demo.webp` is generated by `brand/build-demo.mjs` in the app repo.** Regenerate after UI changes
  so it can't drift into showing a version that no longer exists. The `<source>` is a *format*
  fallback only — one file is ever fetched. A `prefers-reduced-motion` gate was tried and removed: it
  hid the demo from everyone with OS animations off.
- **The narrated video is OFF the page (Oct 2026).** Its end card and voiceover still pitched the
  seven-day trial, so it came out when the app went free. The `.video` CSS, the posters and
  `press/video/` are left in place for when it's rebuilt (`brand/build-video.mjs` already carries the
  new copy; it needs ffmpeg and the voiceover install). The notes below describe it as it was.
- **The narrated video sat under the three steps, not in its own section.** The page alternates
  section backgrounds, so inserting a section here would flip every one below it. `preload="none"` is
  what lets it sit on the page at all — the webm and mp4 are ~1.2MB each and neither is fetched until
  play, so only the poster (85KB) is added weight. **Never swap it for a YouTube embed:** that loads a
  cross-site advertising tracker on every visit.
- **No autoplay.** It runs half a minute with narration. Captions are burned in, so it reads silent.
- **The video is two elements swapped by CSS at 700px**, not one. A 16:9 video in a phone column is
  210px tall and the app inside is illegible. `media` on `<source>` works in `<picture>` but is
  ignored inside `<video>`, so there's no declarative one-element way to do it, and doing it in JS
  would put the demo behind a script. The square cut is 1:1 rather than 9:16 because it runs the full
  beat list, and a 9:16 would stand 747px tall and swallow the viewport.
- The 16:9 poster is the frame at 7.5s — the phrase highlighted with the waveform zoomed to it, which
  is the mechanic the product is. A frame from the ~1.85s gap would keep the control bar off the
  burned-in caption but shows the app idle.
- Requirements sits *below* Open source, so the nav's Download button jumps past it; the Download section
  links back up.

## Newsletter signup

**The form must submit natively. Never `fetch`, never `preventDefault`.** Buttondown's
`embed-subscribe` endpoint only supports a real form submission — subscribers sometimes need to
follow the response to clear a CAPTCHA or fix a validation error.

It previously POSTed via `fetch` with `mode:'no-cors'`. That response is opaque, so the code couldn't
tell success from failure and showed "check your inbox" for every request that didn't throw — anyone
handed a CAPTCHA was told they'd subscribed and silently hadn't. Buttondown detected it and emailed.

`target="_blank"` is what keeps this page open. Don't replace it with Buttondown's iframe or web
component: both fetch from Buttondown on page load, for every visitor, signup or not.

## Campaign attribution

The inline script copies an inbound `utm_campaign` (or `utm_source`, or `google` for a bare Google Ads
`gclid`) into the newsletter form's tag, so signups can be split by campaign in Buttondown. It used to
rewrite the Polar checkout link too; that went with the checkout.

- The campaign is carried across a detour to `privacy.html`, since "read the policy, then sign up" is a
  plausible path and the trip back would otherwise land on a clean URL.
- **Nothing is transmitted, stored or read back.** No cookie, no localStorage, no request — the value
  sits in a form the visitor chooses to submit. Keep it that way.

## Misc

- Internal links use absolute `/`, not `index.html` — the canonical is `https://vocalslice.com/` and
  `/index.html` also serves 200, so a relative link points internal signals at a duplicate URL.
- **The site is deliberately three pages.** Dedicated landing pages (`voice-lines`, `split-by-words`)
  were built and then removed: at ~5 downloads/day the constraint is how many people arrive, not
  landing-page granularity, and every visitor from Show HN, KVR, itch.io and the newsletter lands on
  `index.html` anyway. If a Search campaign ever makes landing-page experience a measured problem —
  see the note in the app repo's `marketing/google-ads-copy.md` — that is the trigger to reconsider,
  not before. The FAQ section on the homepage came out of that work and stayed.
- The header mark and favicon are the same file, generated by `brand/build-icon.js` in the app repo.
- Switching analytics to Plausible or Fathom is a one-tag change, but `scratchpad/utmcheck.mjs`'s
  allowlist needs the new host.
